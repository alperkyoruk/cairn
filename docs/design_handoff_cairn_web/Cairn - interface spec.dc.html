Cairn · web interface

A stack of stones for whoever picks it up next

Design spec for the embedded Vue app: tokens, the status vocabulary, and every screen at desktop width. Dark only in this pass. No webfont, no icon library, no framework — the type is a system stack with Inter first if it is vendored, and the eleven icons on this page are inline SVG.

01

Tokens

Four groups do all the work: ground, ink, rules, roles. Everything on the following screens is one of these; nothing is a one-off value. The ink ramp has four steps because this interface leans on dimness rather than size for hierarchy — a done task and a stale timestamp both recede by losing luminance, not by shrinking.

02

Status

Shape carries the position, luminance carries the demand. A circle means the task is on the pipeline; a check means it has left it; a diamond means it has fallen off the side. Only two statuses are allowed to be bright — review, because it is waiting on the person reading, and blocked, because nothing will happen until they act. backlog and done are the dimmest things on any screen.
backlog Recorded, not chosen. Hollow ring, dimmest ink.
queue Chosen by the human. Same ring, brighter.
active Filled — an agent is on it. Accent, no glow.
review Waiting on you. The glow is the only one in the app.
done Off the pipeline. A check, and it recedes.
blocked Off the side. Different shape, different hue.
The machine, drawn honestly
backlogqueueactivereviewdone
blocked

Never six equal segments. blocked hangs off active on a stem and returns up the same stem. The two human-only transitions — backlog→queue and review→done — are the two segments where the pipeline stops on its own.
03

Task detail

State and worklog are given opposite geometry so they can never be misread as two lists of the same thing. State is a panel: enclosed, raised, three named fields, one byline, no chronology. Worklog is a rail: unenclosed, flush on the page ground, a stack of dated prose running down a vertical line. A panel reads as a record with slots; a rail reads as a history. Field keys are set in mono at 11px, which also says these are three fields of one row, not three sentences somebody wrote.

04

Board

Read-only, one sort, no filters. Rows are 30px tall so a full board fits one screen without scrolling — the five-second glance is the whole use case. Review rows carry a 2px accent mark at the left edge and a one-line count in the header (1 waiting on you) — a readout, not a control: there is nothing to click, nothing to toggle, and the mark survives peripheral vision at the far edge of a wide monitor.

New project

The board is read-only about tasks, not about projects, so this is the one creation affordance it carries: a ghost button on the header line, and a row that opens in place above the table. Two fields, because the second one is permanent — the reference prefix goes into every task reference this project will ever have (bnn-4), and it is the only value in Cairn a human cannot change later.

The prefix is derived, then editable

Typing the name fills the prefix: lowercase, consonant-skeleton to three or four characters, deduplicated against existing projects. binbirnet → bnn, cairn → cairn if it is already short enough. The human can overwrite it before creating and never after.

No modal, no second screen

The board stays behind it, dimmed but present, in the same pattern as the new-task row on project detail. Two inputs and a button do not earn a route of their own, and nothing about creating a project needs the board out of the way.

Deleting a project

Lives on project detail, not here, and reuses the task-delete dialog verbatim — same type-the-reference confirmation, with the count of tasks and worklog entries it takes with it. It is the largest destructive act in the product and deserves no new pattern.

One unit, always. Never 1d 4h, never the word "ago" in the column — the header says it once. Truncate rather than round: 59 minutes is 59m, 61 minutes is 1h.

Weeks stop at four. Past that a relative figure stops carrying information and an absolute date carries more — and a board where the bottom rows read 9 Aug instead of 3w makes the staleness visible rather than arithmetic.

Right-aligned, tabular figures, so the column of numbers lines up and the eye can run down it. The cell's title carries the full local timestamp for anyone who needs the exact minute.

Luminance tracks recency: anything under an hour sits at --text-muted, older rows drop to --text-dim. It costs nothing and the top of the board glows slightly.

10

Open, and deliberately not done

The blocked row borrows its own column

Decided: on a blocked row the next step cell carries blocked_on, in the blocked hue. Same column, same width, no header change — the hue is what says the field is different. It is the only cell in the app whose meaning depends on the row's status, which is worth a comment in the Vue.

Light theme

Only the ground and ink groups need overriding; roles, type, space and radii are hue-stable and carry over. The two things that need real work are the review glow, which reads as a halo on white and probably becomes a filled ring, and --blocked, which needs about 0.15 less lightness to hold the same weight.

Motion

One transition in the app: 120ms on the status mark's colour and the actions row swapping out, so a transition you just made is legible as a change rather than a repaint. Nothing else moves. New worklog entries appear without animation.

Icons

Eleven inline SVGs total: the cairn mark, the theme moon, the chip glyph, the check, the chevron and the warning triangle. Drawn to Phosphor's proportions at 1.5px stroke on a 16px box so a later swap to the real set is a find-and-replace, not a redesign.
